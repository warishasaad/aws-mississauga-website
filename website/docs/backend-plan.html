Summary

What we're building

The public website stays a fast static site. Behind it, a small serverless backend receives form submissions, stores them encrypted in Canada, and only shows them to signed-in organizers with the right role. Members get their own sign-in for the resource library.

Public forms

Volunteer, speaker, sponsor and newsletter forms post to an API that can only write. No one can read submissions without signing in.

Volunteer portal

Organizers and reviewers sign in with multi-factor authentication and see only the submission types they're assigned.

Member portal

Members sign in to see their events and browse slides, recordings and handouts that speakers have approved for sharing.

Why this approach

Everything is serverless, so there are no servers to patch and the cost stays near zero when nobody's using it. All data stays in ca-central-1 (Montréal). The infrastructure is written as code with the AWS CDK, which gives volunteers real AWS projects to learn from.

Architecture

How the pieces connect

flowchart LR
  V([Visitor]) --> CF[CloudFront + WAF]
  CF --> S3[(S3: static website)]
  V -- form submit --> API[API Gateway]
  API --> LF[Lambda: validate and store]
  LF --> DB[(DynamoDB, encrypted)]
  LF --> SES[SES: notify organizers]
  O([Organizer]) -- sign in + MFA --> CS[Cognito: staff pool]
  M([Member]) -- sign in --> CM[Cognito: member pool]
  CS -- token --> API
  CM -- token --> API
  API --> LS[Lambda: role checks]
  LS --> DB
  LS --> R[(S3: private resources)]
  LS --> AUD[(Audit log)]

Organizer emails from SES only say "a new volunteer form arrived, sign in to view". They never include the applicant's details, as the wireframe requires.

Services

What each AWS service does

Amazon S3 + CloudFront

Hosting

Serves the static website over HTTPS on your own domain. A second, private bucket holds slides, recordings and handouts.

Amazon API Gateway (HTTP API)

Front door for data

Public routes accept form posts. Portal routes require a valid sign-in token. CORS allows only the website's domain.

AWS Lambda

Business rules

Validates every field on the server, checks roles on every request, and writes audit entries. Never trusts the browser.

Amazon DynamoDB

Storage

Submissions, members, events, resources and the audit log. Encrypted at rest with point-in-time recovery for backups.

Amazon Cognito

Sign-in

Two user pools: staff (MFA required, groups for Admin and Reviewer) and members (optional MFA). Separate pools keep members away from staff data entirely.

Amazon SES

Email

New-submission alerts to organizers, confirmation emails to applicants, and double opt-in for the newsletter.

AWS WAF

Abuse protection

Rate limits on form routes to stop spam floods, plus a hidden honeypot field on every form.

AWS CDK + GitHub Actions

Deployment

All infrastructure in code, reviewed in pull requests, deployed with short-lived OIDC credentials. No AWS keys stored anywhere.

Revoke access on exit7Disabling a Cognito user and signing them out everywhere ends access immediately.
Export only if authorized7Export route limited to Admins, and every export is logged.

Member profile, events, resource library8Member routes return only the signed-in member's own data and published resources.

Security & privacy

Built in from day one

  • All data stored in Canada (ca-central-1)
  • Encryption at rest and HTTPS everywhere
  • MFA required for every organizer and reviewer
  • Role checks on the server, never only in the browser
  • Least-privilege IAM: each Lambda can touch only its own table
  • No personal data in logs or notification emails
  • Audit entry for every view, change and export
  • Point-in-time recovery backups on every table
  • Automatic deletion after the agreed retention period
  • Rate limits and honeypot fields against spam
  • Privacy notice on every public form
  • Deploys via OIDC, no long-lived AWS keys
Before launch

As the wireframe checklist says, have Ontario or Canadian privacy counsel review the privacy notice, the volunteer confidentiality notice and any NDA. Get written permission before publishing recordings, slides or photos.

from Nov 5

Foundations

  • Create the group's AWS account with a billing alarm and IAM Identity Center logins for volunteers

  • Deploy the current website to S3 and CloudFront

Phase 1MVP

Forms and volunteer portal

  • Staff sign-in with MFA, roles and the first-access acknowledgement
  • Dashboard: view, assign, update status, follow up
  • Organizer email alerts, newsletter double opt-in, audit log

  • Member sign-up with consent and preferences
  • Profile and "my events"
  • Resource library with search and signed file links

Done when a member can sign in and download the Oct 23 slides once the speaker has approved them.

Phase 3Operations

Check-in and reporting

  • QR check-in at events
  • Attendance and engagement tracking
  • Authorized exports for reporting

Done when organizers check in a full meetup from their phones.

Cost

What it should cost

At community scale (a few hundred members and dozens of submissions a month), Lambda, API Gateway, DynamoDB, Cognito and SES should mostly fall within AWS free tiers or cost cents. The steady costs are AWS WAF, which is a few dollars a month for a web ACL and its rules, and the domain name and Route 53 hosted zone. Expect roughly $10 to $15 a month in total. Confirm with the AWS Pricing Calculator before launch, and set a billing alarm in Phase 0.
